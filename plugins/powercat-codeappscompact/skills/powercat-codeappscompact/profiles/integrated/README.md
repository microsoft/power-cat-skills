# Integrated CodeAppsCompact 2.3 application

This app uses the stock accessible workspace and browser-local synthetic data. App definitions are in `src\definition`; independent assertions and host/acceptance bindings are in `tests`. Collections, services, navigation, counts, query refresh and editor guards are already wired. Production authorization/shared storage remain app-owned.

Review the manifest and restore approved dependencies with `--install-links --ignore-scripts --strict-peer-deps --legacy-peer-deps=false --force=false --no-audit --no-fund`. Start the configured server through the authorized workflow. `npm run verify -- --host-route mesh-uia --out <new-run>` requests build, lint, domain/browser acceptance AND authenticated Local Play. Use the emitted request/template with actual authorized Mesh tools. `mesh-browser` or an explicitly authorized existing CDP endpoint are alternatives, never fallbacks after denial.

`npm run finalize -- --resume <run> --host-receipt <fresh-receipt> --events <authorized-stream> --phases <original-markers> --usd-per-credit <explicit-rate>` completes outstanding scopes and returns the usage table/artifacts together. Omit the receipt for CDP; explicitly provide the authorized endpoint. Keep the original marker file open across repairs. `verify:local` is local-only and cannot establish authentication. A `tests\local-play.json` binding requests a reversible synthetic saved-edit check; without it, do not claim edit/reload verification.

Use optional `codeappscompact/authoring` bindings/columns/filters instead of repeated mapping. Keep shared scalar constraints in forms/repository, timeless structure in `validate`, and time/transition policy in `validateMutation`. Business assertions remain independent; do not infer expected answers from implementation. Keep vendor files, lockfile and tools with the app; no source skill path is required. Authentication, publishing and production authorization are separate outcomes.
