QUICK AUTHORING CONTRACT - codeappscompact 2.3.0

The npm kit is prebuilt plain files. Keep the project's vendor folder and lockfile. Existing apps retain their own infrastructure; the complete skill has minimal/example new-app profiles and portable tools. This is a local derivative, not an upstream release or a Mesh installation.

RECORDS
RecordScreen<R,D> must be inside one stable QueryClientProvider. D is a flat object with widened string/number properties; no nested, optional, null, branded or literal-refined payloads. defaults and toDraft(row) have exactly the same own keys/types; all numbers are finite. projectDraft(defaults) copies only those keys, including hidden revision metadata, never backend IDs or extra columns.
Required props: title, queryKey (distinct infinite-query key), service, defaults, fields, columns, getId, toDraft, searchText.
Optional: createDefaults():D, getLabel(row), filters, capabilities, mobileLayout:'table'|'cards', searchScope:'loaded'|'all' (legacy default loaded), headingLevel:1|2|3 (default 1), className, onFormStateChange({dirty,saving}).
defineCollection({namespace,id,...props,toDraft?}) supplies the namespaced key and projectDraft by default. Definitions use ordinary TypeScript objects/callbacks, not a second schema language.

FIELD RULES
Field<D>: name, label, kind:text|email|number|select|reference|textarea|datetime-utc. Optional required, minLength/maxLength, min/max, integer, step, pattern:RegExp, patternMessage, helpText, unit, rows, options, reference. Number defaults are numeric; other defaults are strings. fieldPresets.name/notes/percentage/integer/utc are spreadable.
validateDraft(draft,defaults,fields) returns Map<field,message>; assertValidDraft throws ValidationError. Reuse fields at the adapter boundary. Integer means safe integer; step is relative to min or zero with floating-point tolerance. String rules use trimmed text; numbers cannot represent an optional blank. Numeric zero satisfies required. Pattern checks do not mutate RegExp state. Shape/configuration failures remain explicit errors.
Save trims outer whitespace, preserves internal newlines, rejects invalid input and sends exact draft keys. datetime-utc displays a minute-precision picker explicitly in UTC, not the device time zone. Payload example: '2030-07-20T14:30:00.000Z'. Invalid dates, offsets and precision loss are rejected, not silently truncated. Blank dates are allowed only if optional.
String selects or {value,label,disabledReason?} options remain supported. Values must be unique/trimmed; labels/reasons nonempty. An optional blank select value must be declared. Unknown IDs are not silently replaced; unavailable choices explain why.
Reference fields accept reference:{options,emptyText?} (empty collections allowed) OR {loadOptions(search,signal),resolveOption(id,signal),emptyText?}. Async resolution returns the matching option or null and is separate from search. Stable functions, explicit errors/retry, cancellation/race protection and loading/missing/disabled checks are provided. The data layer still enforces existence/eligibility; UI checks are not authorization.
ValidationError<D>({field:message},message?) attaches domain failures to controls. DataError(kind,message,options?) distinguishes validation/storage/network/conflict/authorization/unknown. Unknown errors are not mislabeled network failures. Failed results/errors never become empty successful collections.

QUERY CONTRACT
DataService<R,D>: getAll(options?:ListRequest), create(draft), update(id,draft), each Promise<IOperationResult<...>> from @microsoft/power-apps/data. List success requires data:R[] and may include a top-level string skipToken. Empty/absent/null token ends paging; other token types fail. IDs are nonempty/stable; loaded duplicates retain the first occurrence.
Optional service.capabilities (or screen override): {search:'local'|'remote',filtering:'local'|'remote',sorting:'local'|'remote',pagination:'none'|'cursor'}. ListRequest adds search, filters, sort:{column,direction}, signal. Advertise only operations the adapter actually implements. Remote view state is included in query keys. Local querying acts only on provided rows and is labeled all or loaded; remote search says service records, not independently verified backend completeness. No cursor may be returned for pagination:none/searchScope:all.
Column<R> keeps header/render; sorting adds required id and sortValue(row):string|number|null. Accessor types must be consistent. Local sorting is stable and locale-aware; null last. Filters have id,label,options and matches(row,value) for local mode. Blank means all. Mobile cards reuse columns; sorting remains available at every width.
Read loading/error/retry and no-record states are explicit. Read errors preserve loaded data. No automatic write retries or optimistic commits. A committed save resets to prevalidated create values, reports Saved, then invalidates its collection prefix; refresh failure is separate and never replays the write.

EDITOR/NAVIGATION
Search/filter/sort and refresh NEVER reset the mounted editor. Key by collection/resource identity, not view state. Dirty Edit/Cancel require confirmation; saves/duplicate submissions/navigation during writes are guarded. getLabel names actions ('Edit <record label>'); fallback uses the ID. Edit moves focus to the form; validation focuses an affected field; Save/Cancel returns to the originating visible row action or search.
useNavigationGuard exposes {formState,onFormStateChange,requestNavigation,message}. Wire every collection action, router link and metric through it; render message as an alert. The kit cannot prevent arbitrary parent unmounts. beforeunload is best-effort, not autosave or guaranteed recovery after termination.

WORKSPACE AND DEMO
collectionKeys(namespace) returns all, workspace and records(id). Use a unique app/data-mode namespace; never mix finite/infinite data under one key. useWorkspace({namespace,repository,dependencies?}) subscribes once and invalidates only this namespace's workspace/affected collection prefixes. repository.read returns a snapshot; subscribe emits {collections:string[]|null}. dependencies maps changed collections to other dependent collections. Unknown/cross-tab changes invalidate this namespace, never all apps. Render error and refreshError; retry() retries the namespace. Keep repository/dependency map stable.
createDemoRepository<Drafts>({key,schemaVersion,defaults,seed,fields?,validate?,validateMutation?,storage?,serialize?,newId?}). Drafts map collections to flat drafts containing revision:number, not id. Defaults revision:0; saved/seeded rows revision>=1 plus id. service(kind) returns complete local collections with declared capabilities; read returns an isolated workspace; subscribe listeners receive changes (old zero-argument listeners still work).
fields reuses scalar validation. validate(next,previous) is structural/referential and runs on initialization/read/write (previous=null on read). validateMutation({collection,operation,id,previous,next}) runs only before create/update persistence. Put future-date/transition/activation policies THERE, not in every read. Do not mutate policy snapshots to rewrite writes. Cross-record/domain meanings and production authorization stay app-owned.
Default storage uses localStorage plus named Web Locks. Missing locks, corrupted/incompatible data, quota/access errors, bad shape/revisions, stale edits and read-back mismatches fail visibly. Existing invalid data is never reset. Demo storage is not a transactional database or durable multi-user backend. Test injection must preserve equivalent serialization, not unsafe Promise.resolve fallbacks in production. Migrations/backup restores must be explicit, validated and authorized.

DISPLAY AND RECIPES
Display tones are neutral/info/success/warning/danger; apps choose mappings. Dates need explicit timeZone (UtcCell supplies UTC) and offset-qualified timestamps. Intl uses the supplied locale or browser locale. Currency needs a currency. Progress validates bounds instead of clamping. Metric/attention actions remain app-owned and must use navigation guards.
Recipes are optional pure helpers, not hard-coded domain rules. reservationConflicts uses half-open UTC intervals/resource IDs and optional buffers. assertTransition/conditionalErrors/assertConditions consume app-defined callbacks/maps. assertFutureDate uses an injected clock and previousValue to restrict creates/rescheduling; enforceUnchanged supports explicit activation policies. createDefaults validates contextual factories; createFixtureTools uses explicit seed/anchor. writeBackup/readBackup/migrateBackup validate JSON, versions and app decoders; they never write/reset storage automatically. See examples/inventory.tsx, service-requests.ts, reservations.ts and backup-restore.ts.

STYLING/HOST/UPDATES
Use data-cc/data-cc-part hooks, not child order or copied markup. Core parts: title/search/search-help/filters/sort-controls/loading/read-error/table-wrap/table/row/edit/load-more/record-cards/form/form-title/error-summary/fields/field/control/field-error/form-error/saved/actions/save/cancel. Shell parts: sidebar/brand/nav-item/nav-icon/nav-label/nav-count/workspace/app-header/skip-link/host-status/visually-hidden. Field kind is data-cc-kind; errors expose data-cc-error-kind. Theme uses --cc-bg/surface/text/muted/accent/border/error/radius/font plus semantic tone/background variables.
AppShell keeps independent accessible navigation labels at all widths. AppErrorBoundary logs render errors and preserves storage. Neither creates another query provider. PowerAppsHostStatus distinguishes preview/checking/authenticated/failed without retaining identity/session values. A real authenticated Local Play claim additionally requires the matching Power Apps parent and loopback frame; mocked contexts, CLI profiles and localhost previews do not count.
2.1 is additive to the 2.0 runtime except more specific row action names and opt-in constraint enforcement. Default new-app profile is now minimal; choose --profile example for the neutral two-collection demo. Default record layout remains table. setup.mjs refuses to overwrite a different/customized kit: use a reviewed app dependency update. Existing app source, profiles, data keys and production behavior are never migrated automatically.

2.2 INTEGRATED WORKSPACES (OPTIONAL)
codeappscompact/workspace exports collectionView, CollectionWorkspace, defineDemoWorkspace and DemoWorkspace. Existing 2.1 APIs remain available; this module is opt-in. Prefer the selected generated signature in the skill's references/signatures rather than reading this whole compatibility document.
collectionView(screenWithId,count?) captures a typed RecordScreen configuration as a heterogeneous WorkspaceView without losing its row/draft types. CollectionWorkspace({title,subtitle?,hostStatus?,collections,initialId?,metrics?,attention?,children?}) provides guarded navigation, optional counts/default count metrics and attention actions. A metric collectionId or attention action.collectionId must name an actual view and is routed through the same dirty guard. Custom WorkspaceView.render callbacks and real-service collections remain supported.
defineDemoWorkspace<Drafts> extends the existing DemoOptions with required shared fields and one collections[key](state) callback per draft key. A callback returns normal collection props without repeated namespace/id/service/defaults; an optional fields override adapts presentation (for example relationship labels), not business policy. The wrapper supplies namespaced services/queries and projects exact drafts. Optional dependencies, metrics(state) and attention(state) stay app-owned. It returns a stable definition consumed by <DemoWorkspace definition={definition} title={title} hostStatus={...}/> under the starter's existing query provider/error boundary.
The skill's --definition path creates an integrated application and test entry points from plain TypeScript plus independent domain/acceptance cases. It does not evaluate definitions during copying, infer policies, create a second storage framework or authorize execution. Use the complete skill's authoring/tooling guides for resumable verification; no standalone preview can certify authenticated Local Play. No lower model cost is implied without a controlled benchmark.
